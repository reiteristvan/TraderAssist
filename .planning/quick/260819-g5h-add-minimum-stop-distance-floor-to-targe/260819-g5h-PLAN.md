<objective>
Add a minimum stop-distance floor of 0.5 x ATR to the stop engine in `scanner/targets.py`, so that a stop can never sit closer to entry than half an ATR. Today the pullback rule (`EMA20 - ATR`) and the breakout rule (`high20 - 0.5 x ATR`) have no minimum distance; when price closes just above the computed stop level, risk-per-share collapses toward zero, producing unexecutable trades and corrupting every downstream R-multiple metric (`r_multiple`, `target_r`, `mae_r`, `mfe_r`) and the risk-based sizing formula.

This CHANGES TRADING LOGIC and is the explicitly approved, data-backed task that CLAUDE.md requires before altering stop rules. Approved by István on 2026-08-19 against backtest run `4f4fe68_2021-01-01_20260702_090418`.

Purpose: 15 trades with `|r_multiple| > 10` currently flip the pullback strategy's sign (raw mean R +0.051 vs -0.007 winsorized at 10R). EPAC 2024-01-16 shows 2.4 cents of risk against a 0.71 ATR (0.03 x ATR) producing 72.7R; sizing that at 1% on a $50k account demands 20,833 shares = $602k of stock.
Output: One module constant, one pure helper, one call site, and a regression test block. No schema change, no new flag, no gate or score change.
</objective>

- **D-01 — Floor multiplier is 0.5 x ATR.** Chosen on execution-realism grounds, NOT by maximizing backtest expectancy. 3. **`tests/test_targets.py::test_stop_formula_pullback` will stay green untouched.** Measured stop distance on the same fixture is **4.413 x ATR** — the floor does not bind.

4. **`test_attach_risk_stop_above_entry_safe` pins a real trap.** Its declining fixture (`r=-0.005`) produces a stop distance of **-8.482 x ATR** — the stop is ABOVE entry. A naive unconditional `min(strategy_stop, entry - 0.5 x ATR)` would move that stop from 5.40 down to ~4.92, converting a correctly-neutered degenerate signal into a tradeable one. That is an unintended behavior change. Guard order is therefore load-bearing and is specified explicitly in Task 1.

5. **`min()` is NaN-order-dependent.** In Python `min(x, nan)` returns `x` but `min(nan, x)` returns `nan`. Correctness must not rest on argument order — an explicit finite/positive check is required.
</prior_investigation>

    3. Add a module-level pure function `apply_min_stop_floor(stop, price, atr, mult=MIN_STOP_ATR_MULT)` returning a float. It must be total — no code path raises. Contract:
       - Coerce `stop`, `price`, `atr` to float inside a `try`; on `TypeError`/`ValueError` (covers `None`) return the input `stop` unchanged.
       - If any of the three is not finite (`math.isfinite`), or `atr <= 0`, return the input `stop` unchanged. Do NOT rely on `min()` to propagate or suppress NaN — its result depends on argument order (see prior_investigation item 5).
       - Compute the floor candidate by quantizing DOWNWARD to the cent: take `price - mult * atr` and floor it to two decimal places using `math.floor(value * 100) / 100`. Use floor rather than `round` deliberately: `round` can land the resulting risk up to half a cent SHORT of `mult * atr`, which would break the strict invariant the regression tests assert. Record that reason in a brief comment.
       - If the floor candidate is not strictly less than `price` (only reachable when `mult * atr` is under one cent), return the input `stop` unchanged — the caller has already established that the raw stop sits below entry, so returning it keeps the result valid and avoids emitting a stop at or above entry.
       - Otherwise return `min(stop, floor_candidate)`, which can only widen (D-02).

    4. Wire exactly one call site inside `attach_risk`, placed AFTER the existing `if stop >= price:` early-return block and BEFORE the `compute_targets(...)` call, reassigning `stop`. Placement is load-bearing in both directions:
       - Placing it after the early return preserves the current stop-at-or-above-entry contract exactly; a degenerate stop stays neutered rather than being rescued into a tradeable signal (see prior_investigation item 4).
       - Placing it before `compute_targets` means the floored stop feeds the risk denominator, so `risk_reward` reflects true risk rather than the collapsed value.
       Add a brief comment at the call site naming the quick-task id and the approval date so the trading-logic change is traceable in blame.
