<objective>
Add an opt-in, backtest-only cluster suppression rule: when the same ticker has already
produced >= N qualified signals in the trailing D calendar days, drop the next qualified
signal. Ships as `--cluster-limit` / `--cluster-window` on the `backtest` subcommand,
default OFF, so the hypothesis can be A/B tested on a single commit.

Locked decisions from CONTEXT.md (aliases for the coverage gate: D-01 = D1, D-02 = D2,
D-03 = D3):
- **D1 / D-01** — qualified-only: only `qualified=True` signals increment the window and
  only they can be suppressed; near-misses pass through untouched.
- **D2 / D-02** — a suppressed signal STILL records its date into the window.
- **D3 / D-03** — CLI flag, default OFF; setting recorded in `run_meta.json`.

Purpose: measure whether repeated same-ticker signals inside a short window are the
net-loss cluster the prior backtest review suggested. This is a hypothesis test, not an
accepted edge — nothing about the live scan changes.

Output: suppression logic in `scanner/backtest.py`, CLI plumbing in `scan.py`, one
conditional reporting line in `scanner/report.py`, and `tests/test_backtest_cluster.py`.
</objective>
