## Overview

This milestone added two capabilities to TraderAssist: industry-group momentum as a display field on every signal, and winner/loser characteristic analysis in backtest reports. The work proceeded in four phases: validate the industry classification and ETF data layer, compute and store momentum scores under schema v9 with full look-ahead bias prevention, surface the fields in CLI and web UI, then deliver the pre-registered W/L analysis in backtest reports.

## Milestone Summary

**Key Decisions:**

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Display-only for industry momentum | Evidence-first discipline (same that prevented ADX/volume-contraction gate removal mistakes) | ✓ Validated — industry fields visible in CLI + UI; gate promotion deferred to v2 pending backtest evidence |
| Industry group granularity over GICS sectors | Finer discrimination — sectors too broad for 5-20 day swing hold | ✓ Validated — `industryKey` slugs from yfinance map cleanly to SPDR ETF proxies |
| Winner vs loser analysis in backtest reports | ~50% stop rate with gate compliance suggests the answer is in the entry-metric distribution | ✓ Delivered — pre-registered 6-metric analysis with anti-cherry-picking guard (WLA-06) |
| `WL_FEATURES` pre-registered before any run viewed | Anti-cherry-picking: feature list must not be influenced by observed results | ✓ Enforced — `WL_FEATURES` constant committed in `report.py` before backtest results evaluated |
| 3-tuple signal key `(date, ticker, strategy)` in `sig_by_key` | Prevents W/L collisions in mixed-strategy backtest runs | ✓ Correct — needed for dual-strategy runs where same ticker appears in both strategies |
| Schema v9 (not v7 as initially named) | v7/v8 already consumed by prior work; v9 is the correct next migration step | ✓ Accurate — schema_version = 9 in production DB |
| `industry_above_50ma` stored as integer (0/1) not bool | SQLite boolean semantics: 0/1 integers, not Python True/False | ✓ Applied — integer-equality checks (`== 1`, `== 0`) used throughout display code |

**Issues Resolved:**

- Look-ahead bias in backtest ETF momentum: fixed by per-day ETF anchoring with sliced market data before the ticker sub-loop (consistent with existing SPY anchoring pattern)
- `bool(NaN)` coercion returning `True` for MACD pre-warm-up signals: fixed with `pd.isna()` guard in backtest.py (code review finding WR-03)
- JSON.parse crash in Express API on malformed SQLite data: fixed with `safeParse` helper (code review finding CR-01)
- Signal key collision in dual-strategy W/L analysis: fixed with 3-tuple key `(date, ticker, strategy)` (code review finding CR-02)
- Angular subscription memory leak: fixed with `switchMap` + `takeUntil(this.destroy$)` pattern (code review findings WR-04/WR-05)

**Issues Deferred:**

- IND-EXT-01: Industry rank delta vs 4 weeks prior (momentum-of-momentum) — v2
- IND-GATE-01: Industry momentum as a hard gate — v2, contingent on backtest evidence
- WLA-EXT-01: Statistical significance indicators (p-values / CIs) — v2
- WLA-EXT-02: Time-series view of win rate by quarter — v2

**Technical Debt Incurred:**

- None significant. Code review fixed all 12 findings before milestone close.
- `industry_momentum` REAL column holds signed percentage (e.g., `3.2` = 3.2% outperformance vs SPY) — unit is implied, not stored. Future display changes must maintain this convention.
