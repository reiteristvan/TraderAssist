    `get_earnings_dates`'s three-branch structure:

    2. Cache-hit branch: if `not refresh and path.exists()`, wrap `pd.read_parquet(path)` in try/except; read the
       single stored value from a `sector` column — if the frame is empty (the sentinel) return None, else return the
       string. On any read exception, `pass` and fall through to refetch (mirror earnings_store.py:35-43).
    3. `_CACHE_DIR.mkdir(parents=True, exist_ok=True)`.
    4. Fetch branch wrapped in try/except: define `_fetch()` returning `yf.Ticker(ticker).info.get("sector")`, call

       `pd.DataFrame({"sector": [sector]})` to `path` and return the sector. If the result is falsy (None/empty),
       fall through to the sentinel-write path below and return None.
    5. Except branch (or unresolved sector): `_log.warning("get_sector: %s failed: %s", ticker, exc)` on exception,
       then write the empty sentinel `pd.DataFrame({"sector": pd.Series([], dtype="object")}).to_parquet(path)`
       inside its own try/except (mirror earnings_store.py:69-76) and return None. This is the D-03 "skip silently,
       don't abort" behavior plus the anti-retry-storm sentinel.

    Do NOT add a second yfinance import path anywhere else in the codebase — this module is allowed to import
    yfinance because it is a cache module in the same tier as earnings_store.py.
