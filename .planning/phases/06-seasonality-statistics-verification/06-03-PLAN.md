<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI args (`--bootstrap-iters`, `--seed`) → engine | user integers pass through `main()` into `compute_seasonality_stats`, which forwards them to the validated bootstrap |
| engine `ValueError` → CLI exit code | thin-data / iters guards raised in the module are turned into exit code 2 at the thin CLI wrapper |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-6-01 | Tampering / Denial of Service | `--bootstrap-iters` pass-through | medium | transfer | Validation is enforced downstream in `bootstrap_week_ci` (Plan 02): a non-positive `iters` raises `ValueError` before array allocation. This plan's CLI catches that `ValueError` and returns exit code 2 with the message on stderr, mirroring the existing sector/universe error path — the guard is not re-implemented here, only surfaced cleanly. |
| T-6-05 | Denial of Service | thin-data abort path | low | mitigate | `compute_seasonality_stats` calls `check_thin_data` before the bootstrap; a dataset with <5 distinct years aborts with a clear `ValueError` (exit 2) rather than computing a dishonest CI on too few blocks (D-05). |
| T-6-SC | Tampering | package installs | low | accept | No new package-manager installs — numpy/pandas already vendored. No legitimacy gate required. |
</threat_model>
